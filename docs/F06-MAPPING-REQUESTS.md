Appointments grant only individual mapping-decision recording for an exact policy and external acceptance. This is a narrow feature capability on top of active estate-manager/customer setup scope, not completion of configurable production role/staffing/quorum administration. Current recorded approval is not an application permit or collective/production sign-off. The workflow does not execute overlays, rewrite historical attribution, modify task links, change quantities/shares/states or dispatch payroll/finance. Actual client authority, custody and staffing acceptance remain human inputs and release gates.

Submission binds the complete latest-per-reviewer observation identity/revision/scope-marker set, not only the25 details shown in earlier readiness summaries. Every current concern, insufficient statement or changed reviewer authority blocks submission. Revocation does not erase adverse observations. Existing source corroboration checks are a preliminary request gate, not a new claim that client evidence-count/quorum criteria have been machine-certified. Duplicate source/record rows, stale work, existing company attribution, missing/foreign targets, inactive estate and task-block proposals cannot enter this work-company request flow. Existing exact-code task linking remains separate. Batches retain the existing1–50-row manifest bound; accepted high-volume staging remains open.

The transaction serializes policy/acceptance/appointment/request/decision/provenance changes per estate, holds relevant actor/grant/record/target rows and compares a freshly derived binding to the submitted immutable snapshot before recording approval. Requester or reviewer scope changes require renewed review; restoring access alone does not revive the old snapshot/appointment. Read-only inspection spans a read window and is not a reusable write permit. Raw helper lock paths are not executable by runtime callers and raw membership/setup RLS is unchanged.

Return/rejection are individual terminal decisions for that submission. Returned or withdrawn requests can have one linked correction by the original requester, including a corrected saved manifest/source check when required. An approved decision can only receive a separate withdrawal event; it cannot be edited into another outcome. Exact retries recover old receipts without approving or reinstating changed authority. An existing unchanged-scope appointment may record a negative decision/withdrawal for its exact older policy after policy drift; new positive approval always requires the current accepted binding. Fully revoked scope pauses recording and retains history.
